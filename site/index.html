Verifiable or confidential. Most systems make you pick one.

Public ledgers make everything provable and everything visible, which rules them out for competitively sensitive data. Private databases keep that data quiet but ask every verifier to trust the operator. Domain platforms solve it once, inside one silo, with disclosure rules nobody outside can inspect.

Regulation now asks for both at once. The EU Digital Product Passport, the EU AI Act, and SEC climate rules all want histories that an outside party can check without handing that party the whole record.

Generate locally. Commit through a confidential backend.

Record the history

Every assertion is an append only event on a graph, signed with Ed25519 and addressed by a decentralized identifier. Nothing is edited and nothing is deleted, so the history stays tamper evident by construction.

Commit the proof, not the data

Sigil computes Merkle roots over the record and commits them through the active confidential backend. The raw provenance never has to leave your infrastructure to become verifiable.

Disclose against a policy

A recipient asks for fields. The policy engine decides what they may see, and the backend returns a receipt recording who received which fields when. That receipt becomes part of the audit trail itself.

The confidential layer is a component, not a commitment.

Sigil owns the provenance model, the trust graph, the attestation schema, and the disclosure logic. The network that proves and settles sits underneath a single interface of five methods, so swapping it is an adapter change rather than a redesign.

What ships today.

Sigil is early. The engine underneath is real and tested. The cryptographic enforcement of disclosure is not built yet, and this page says so rather than implying otherwise.

Shipping now

The provenance engine works end to end today. Ed25519 identity, a SQLite graph store, the five level policy ladder wired into the SDK, and a local backend.

Integrate once.

One SDK call records a lot, one certifies it, one discloses a subset to an auditor. The same code runs against any backend.

Get started 
// record a lot, certify it, then disclose to an auditor
const sigil = new Sigil({ backend: "local" });

const lot = await sigil.asset.create({
  type: "batch-lot",
  owner: farmerDid,
  metadata: { origin: "Huila, CO", variety: "Caturra" },
  visibility: VisibilityLevel.Partner,
});

await sigil.event.record({ assetId: lot.id, type: "certified",
  metadata: { scheme: "FairTrade" } });

const receipt = await sigil.disclose({
  assetId: lot.id,
  recipient: auditorDid,
  level: VisibilityLevel.Auditor,
  fields: ["origin", "cert"],
});
